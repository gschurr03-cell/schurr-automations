## What changed

The managed sales block in `lib/receptionist-sales.ts` now gives the receptionist concise, spoken answers for all four service areas, the founder's role, the build process, existing-software questions, pricing and the exact approved guarantee. Discovery follows the caller's problem and stops when they are ready for the next step. The copy does not require a particular customer value, recite research statistics or turn every inquiry into an AI-receptionist pitch.

Client installation capabilities are kept distinct from this agent's connected actions. The website's 15-minute invitation does not override the live calendar duration. One-ring and subminute response claims remain installation targets. Research is external evidence, not Schurr client results. Prices and implementation timelines are scoped individually.

The greeting, provider voice, model, pacing, tools, number routing, capture rules and managed appointment rules are unchanged. This refresh is intended for the user's selected Chloe voice without changing the voice itself.

## Apply to the existing phone agent

Publishing the website makes this script available in the CRM; it does not itself change the remote Retell conversation. In `/manage/receptionist`, the owner uses **Update receptionist script and tools**. The existing `sync_voice` action installs the managed sales and operations blocks into the verified routed latest draft. It checks the route, preserves unrelated configuration and verifies the result. Published or stale routed versions fail closed and require review in Retell. No extra authentication path or public update endpoint was added.

## Short call review

After the CRM reports success, check an inquiry about missed calls, a website rebuild, a Google/AI-search question and a price or guarantee question. Confirm the answers fit the service, remain brief, and do not invent prices or outcomes. Interrupt the opening once and confirm it continues without restarting. If booking is tested, the connected tools and their actual results must govern availability, permission and confirmation. A browser dry run is not a real appointment.

Source-level synchronization checks verify prompt installation and unchanged voice/routing. They cannot prove how the conversation sounds or that the remote agent has received this revision before the owner applies it.
